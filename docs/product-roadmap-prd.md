## 1. 规划总览

本 PRD 覆盖五个工作包，按建议实施顺序排列：

| 工作包 | 内容 | 成本 | 解决什么 |
|---|---|---|---|
| **N｜全站导航重构** | 统一导航组件 + 跨页动线补全 | 低 | 「路径不顺畅」——页面之间断路、四套导航不一致 |
| **A｜画布迭代手感** | 参数继承/自动选中/自动平移/取消 | 低 | 画布核心动作每轮多 3 次操作 |
| **B｜复现与资产** | 广场复现闭环 + 配方快照 + 参考图库 | 低-中 | 转化与复用，后端数据已齐 |
| **C｜架构拆分（C0）** | src/shared + src/canvas 抽离 | 中 | D 包的前提，方案已在 canvas-v2-prd §5 |
| **D｜画布差异化** | 派生把手/扇形变体/换种子/双图对比 | 中 | 竞品验证过的核心手势 |

明确不做（沿用 review 结论）：视频/3D、多人协作、广场评论、用户可编辑节点流、类型化端口。

## 2. 工作包 N · 全站导航重构

### 2.1 现状盘查（问题定义）

全站五个页面，**四套手写导航，无共享组件**。逐页核实：

| 当前页 | 顶栏可去往 | 实现位置 | 问题 |
|---|---|---|---|
| 首页 | 工作台 / 画布 / 广场 + 管理图标 + 登录 | `home-topnav` | ✅ 唯一完整的；品牌点击 = 回页顶 |
| **工作台** | 首页 / 广场 | Studio `topbar` | ❌ **无画布入口**（使用时长最高的页面反而进不了画布）；无品牌 logo |
| 画布 | 首页 / 工作台 / 广场 | `canvas-topbar-nav` | ✅ 项目齐；顺序与首页不同 |
| 广场 | 工作台 / 画布 / 首页 | `square-topbar-actions` | 项目齐；顺序又是第三种 |
| 管理 | 首页 / 工作台 | AdminApp | 可接受（低频入口，刻意隐蔽） |

具体不一致点：

1. **入口缺失**：Studio → 画布断路。这是唯一的功能性断点，其余是一致性问题。
2. **顺序三套**：首页「工作台/画布/广场」、画布「首页/工作台/广场」、广场「工作台/画布/首页」。用户每换一页，导航按钮位置都变。
3. **图标语义混乱**：Studio 里「首页」用 `WandSparkles`（魔棒）、「广场」用 `ExternalLink`（外链图标——暗示会离开应用，实际是内部页面）；广场里「工作台」也用 `WandSparkles`。同一图标在不同页面指向不同目的地。
4. **品牌行为不一致**：首页品牌=滚回顶部，画布/广场品牌=回首页，Studio 没有品牌位。
5. **无当前页指示**：现有模式是「导航里省略自己」，但 Studio 连画布也省了，导致「省略=当前页」的心智模型失效。

**路由层是健康的，不要动**：hash 路由 + `pushState`、`normalizePathToHash`（`/studio` 直链规范化为 `/#studio`）、`#admin/logs` 深链、hashchange 后退——全部已实现且工作正常。本工作包只改导航 UI 层。
（顺带：CLAUDE.md 里「P3 深链管理后台 tab 未实现」是过时描述，代码已实现，见 AdminApp 的 tab-hash 同步。）

### 2.2 需求

**N1 · 统一导航组件 `AppNav`（P0）**

- 一个共享组件，五个页面全部接入（管理后台可用精简变体）。
- 固定顺序：**首页 · 工作台 · 画布 · 广场**（与首页现有顺序一致，首页是流量入口，以它为准）。
- **显示当前页并给激活态**（而不是省略当前页）：激活态用 `--text` 加粗 + 底部 2px 指示条，不用品牌绿填充（60/30/10 原则，导航不是品牌时刻）。
- 图标规范（lucide，全站统一）：首页 `House`、工作台 `WandSparkles`、画布 `LayoutDashboard` 或 `Frame`、广场 `Users`/`Compass`。**禁用 `ExternalLink` 于站内导航**。
- 品牌位统一：logo + "Image Studio" 常驻左侧，点击回首页；当前在首页时点击回页顶。Studio 补上品牌位。
- 页面级徽标（Canvas/Square badge）保留，放品牌右侧。
- 样式使用既有 token（`--surface`/`--border`/`--r-pill`/`--dur-fast`），画布暗色作用域下自动继承（`AppNav` 不得硬编码浅色背景，教训见 `.subtle-button` 反转失效案例）。

验收标准：
- [ ] 任意页面顶栏可一键到达其余三个主页面；四个页面按钮顺序、图标、激活态完全一致
- [ ] Studio → 画布可达
- [ ] 画布暗色作用域内导航无对比度问题（对比度 ≥ 4.5:1）
- [ ] 移动端（≤780px）导航可横向滚动或收纳，不换行挤压（首页已有滚动处理，统一后沿用）

**N2 · 跨页动线补全（P1）**——导航栏之外的「路径不顺畅」：

| 动线 | 现状 | 需求 |
|---|---|---|
| Studio 图片 → 画布迭代 | 断路（只能下载再拖入画布） | 历史记录/结果卡片加「在画布中打开」：图片作为节点落入画布并选中，进入优化模式 |
| 画布节点 → Studio | 断路 | 节点右键菜单加「发送到工作台」：prompt+params 填回 Studio 表单 |
| 广场 → 复现 | 断路 | 见工作包 B（B1） |
| 跨页任务感知 | 在广场/画布逛时，Studio 任务完成无任何提示 | 全局任务角标：导航栏「工作台」项上显示进行中任务数，完成时 toast（复用已有对账轮询数据，不新增请求） |

验收标准：
- [ ] Studio 任一成功记录两次点击内出现在画布上且已选中
- [ ] 任一页面可感知进行中/刚完成的生成任务

**N3 · 首链体验（P2，低成本顺手做）**

- `normalizePathToHash` 白名单已覆盖 4 个 path；补 `/login` → 触发 OAuth（分享登录入口的真实场景）。
- 404 hash（如 `#xyz`）静默落回首页——保持现状，但补一个 toast「页面不存在，已回到首页」。

### 2.3 技术约束

- 不引入路由库。现有 hash 机制够用，加 router 是负资产（单文件架构下反而增加拆分难度）。
- `AppNav` 放入 `src/shared/`（配合工作包 C），**不 import App.tsx**，导航目标经 props 回调传入——与现有 `onEnterStudio` 等回调模式一致。

## 3. 工作包 A · 画布迭代手感（全部低成本）

问题定义：画布的差异化价值是「探索路径可视化」，但一轮迭代 = 选节点 → 按 E → 填补充词 → 生成 → **手动找新节点** → **手动选中** → **手动检查参数没被上一轮污染**。竞品（Krea/Recraft/Flora）后三步为零。

| # | 需求 | 规格 | 验收 |
|---|---|---|---|
| A1 | 优化参数继承原图 | `enterOptimizeMode` 时从源节点 `params` 回填模型/宽高比/分辨率/质量；下拉首项「继承原图（默认）」，用户改动即脱离继承 | 用 A 参数生成 → 改面板为 B → 优化该图 → 请求参数是 A |
| A2 | 新节点自动选中 | 优化生成的子节点创建后即 `selectOnly(newId)`，面板保持优化模式且源切换为新节点 | 连续按 E-填词-生成三轮，全程无需点选节点 |
| A3 | 视口自动平移 | 新节点（生成/优化/重试）若中心在视口外，300ms 平移使其可见（`--dur-layout` + `--ease`；`prefers-reduced-motion` 时瞬移） | 缩到 10% 在角落生成，节点必然可见 |
| A4 | 取消生成 | 生成中节点浮层与面板提供「取消」：前端节点标记 cancelled 并停止对账该 id（服务端任务照跑完，结果丢弃——后端无取消 API，不新增） | 取消后节点消失或标记，不再转圈 |
| A5 | 失败节点面板详情 | 选中失败节点时面板显示错误消息 + 重试 + 复制错误 | 失败后不进右键菜单也能重试 |
| A6 | 转圈兜底 | 对账连续 N 次（建议 24 次 ≈ 2 分钟）查无该 requestId 时节点转为失败态「任务已丢失，可重试」 | 手工造一个假 requestId 节点，2 分钟内变失败态 |

顺带修复（同一批提交）：视口位置落盘（auto-save 依赖加 viewport，防抖 1000ms 与拖拽 500ms 分开）、Studio 顶栏画布入口（并入 N1）、`duration` 死代码（对账落图时用 `stages` 算出耗时写入，恢复右下角耗时角标）、失败浮层「复制错误」。

## 4. 工作包 B · 复现与资产

### B1 · 广场复现闭环（P0，后端数据已齐）

- 广场详情页展示生成参数：prompt、模型、尺寸、宽高比（数据源 `request_logs.data.params`，经 `/api/square/*` 下发需**新增字段**——注意：只下发参数本身，**不得携带 imageId/目录路径/clientId**，沿用 feed 的脱敏纪律）。
- 发布到广场时可勾选「隐藏提示词」（默认公开；尊重创作者）。
- 「用同款参数生成」按钮：参数填回 Studio（模型不在当前站点白名单时给出提示并保留其余参数）。

验收：广场任意公开参数的作品，两次点击内在 Studio 里参数就位、可直接生成。

### B2 · 配方快照（P1）

- 任一成功生成（Studio 记录/画布节点/广场复现）可「存为配方」：命名的 prompt+params 组合，存前端 IndexedDB。
- Studio 与画布的参数面板顶部提供配方下拉；应用配方 = 整组回填。
- 上限 50 个，可删除、可导出 JSON（随浏览器数据走，不上服务端）。

### B3 · 参考图库（P1）

- 参考图可命名收藏进前端 IndexedDB（**不落服务端**，维持「参考图只存内存 10 分钟 TTL」的服务端红线）。
- 上传参考图处提供「从图库选择」，跨 Studio/画布复用。
- 这是对竞品「角色/风格一致性」（Midjourney --cref、Lovart 画布记忆）在 BYO-Key 架构下的等价实现：一致性靠稳定复用同一组参考图达成。

### B4 · 历史记录筛选（P2）

Studio 侧栏历史支持按状态/模型筛选 + prompt 关键词搜索（IndexedDB 游标过滤，无后端改动）。

## 5. 工作包 C · 架构拆分（C0）

方案已定稿于 [canvas-v2-prd.md](canvas-v2-prd.md) §5，本 PRD 不重复，只锁定三点纪律：

1. **两步走**：先逐字搬迁（git diff 可校验等价），后重构。禁止合并成一次提交。
2. **五个坑**必须逐条对照（`.canvas` ≠ Canvas Mode、`openDb` 唯一实现、`runtime*` 单例、tsconfig 无 noUnusedLocals、CSS token 注入顺序）。
3. 验收不止 `tsc -b`：冷启动加载历史画布 → 生成 → 优化 → 刷新持久化，四步人工回归。

新增一条：`AppNav`（N1）与 B2/B3 的 IndexedDB 工具应直接落在 `src/shared/`，**不要先写进 App.tsx 再搬**。

## 6. 工作包 D · 画布差异化（依赖 C 完成）

| # | 需求 | 规格要点 | 参照 |
|---|---|---|---|
| D1 | 派生把手 | 选中/悬停节点右缘出现把手，拖出松手 = 在落点建优化子节点并聚焦补充词输入；Esc 取消 | ComfyUI / Krea Nodes |

## 7. 里程碑与度量

| 里程碑 | 包含 | 完成定义 |
|---|---|---|
| M1（1 个迭代） | N1 + N2 + A1–A6 + B1 | 四页导航统一；画布三轮连续迭代零多余点击；广场可复现 |
| M2 | C0 + B2 + B3 + N3 + B4 | App.tsx ≤ 约 10500 行；配方/参考图库跨端可用 |
| M3 | D1–D5 | 派生把手 + 扇形变体上线 |
| M4（观察后决策） | D6、Agent 画册落画布、Inpaint/Outpaint | 前置：admin 观察 Agent 使用量；确认上游 mask 协议 |

度量（现有埋点即可支撑，无需新增采集）：
- 画布：人均迭代链深度（edges 链长）、优化动作占生成总量比例 —— M1 后应显著上升
- 广场：「用同款参数生成」点击 → 实际生成的转化数（daily_stats 可加一行 source 维度，注意 `ALTER TABLE` 纪律）
- 导航：无直接埋点，以用户反馈验证（本产品无行为追踪，隐私模型优先，**不为度量加追踪**）

## 8. 风险与红线（实施时逐条自查）

1. 广场下发参数时**绝不携带** imageId / 目录路径 / clientId（隐私模型）。
2. 参考图库仅存前端 IndexedDB，服务端仍然只有 10 分钟内存 TTL。
3. `AppNav` 及一切新共享组件：颜色与背景**都**取 token（画布暗色作用域反转教训）。
4. 新 CSS 全部走 token（`--r-pill`/`--dur-fast`/`--ease`…），零字面量；`transition: all` 保持 0。
5. 画布数据模型改动（D2 扇形、D5 pin 字段）需同步 IndexedDB 持久化结构并向后兼容旧 canvas-state。
6. daily_stats 加列必须 `ALTER TABLE` + PRAGMA 检查 + 回填（CREATE TABLE IF NOT EXISTS 不会加列）。
